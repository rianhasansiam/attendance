# State/data-flow audit

Inspected the existing source, lockfile, repository instructions and installed Next.js documentation before editing. The baseline worktree was clean. This document separates existing defects from requested improvements; lack of Redux or a cross-user push mechanism was not itself a defect.

## Baseline

- Installed Next.js 16.3.5, React 19.2.8, Prisma 7.10.0, Auth.js 5.0.0-beta.32; `package.json` specifies pnpm 12.3.4. Major versions and the PostgreSQL driver are preserved.
- `next.config.ts` enables Cache Components, registers the `referenceDisplay` cache profile and builds standalone output. All API responses use HTTP `Cache-Control: no-store`.
- `vitest.config.mts` runs Node unit/integration tests; PostgreSQL tests opt in through `TEST_DATABASE_URL`. `tsconfig.json` uses strict TypeScript, Next-generated types and App Router conventions.
- Baseline `pnpm lint` and `pnpm typecheck` passed.
- Baseline `pnpm test`: **21 files / 354 tests passed; 4 files / 27 tests skipped**. The skipped suites require an explicitly isolated test database. No locking, SQL constraint or trigger guarantee is claimed as freshly executed verification from these skipped suites.
- `ops/attendance.service.example` describes one Node process bound to localhost behind `ops/nginx.conf.example`. No live deployment or actual replica count was inspected.

## Missing capabilities and architecture improvements

At baseline, interactive screens used independent `useResource` subscriptions and imperative mutations, with screen-local reloads. The requested RTK Query migration supplies shared subscriptions, explicit dependency invalidation and documented freshness. These are implementation improvements rather than evidence that every baseline read was incorrect. The profile remains server-rendered and does not acquire a duplicate client subscription.

Read [`state-management.md`](state-management.md) for the implemented client architecture, ownership, invalidation matrix, identity cleanup and freshness policies.

## Behavior deliberately preserved

- `src/auth.ts` permits only pre-authorized Google identities, rejects public account creation, uses database sessions, avoids persisting Google tokens and returns an explicit session display allowlist. `src/lib/auth.ts` rechecks the persisted unexpired session, active user and bound Google identity on protected requests. Role/status changes delete affected sessions in employee/management modules.
- `prisma/schema.prisma` keeps `User.employee Employee?`; administrators can exist without employment details. Employee-only access uses `requireEmployee`/`requirePageEmployee` and the shared profile guard.
- Attendance corrections require `SUPER_ADMIN` in both their routes and workflow functions, including fresh current-role/status checks in their existing transaction. Payment status remains `SUPER_ADMIN`; drive management retains its existing separate permission.
- `src/modules/attendance/service.ts` retains server-owned timestamps, fresh policy/network/device reads, employee row locks, serializable transactions, current-session rechecks, open-check-in protection, audit/events and timezone logic.
- `src/modules/webauthn/service.ts` retains atomic single-use challenge consumption bound to employee/session/purpose/expiry; consumption commits separately so a failed verification cannot reuse the challenge. Origin, RP ID and user verification remain checked by SimpleWebAuthn.
- `src/modules/network/service.ts`, `src/lib/security.ts` and the Nginx example retain trusted-proxy/IP enforcement, origin validation and rate limiting. No authentication bypass was added.
- The initial migration includes attendance-per-day uniqueness, the partial one-open-attendance index and append-only audit/event triggers. Later migrations retain overtime and exact Decimal financial checks, including round trips and payment status. This refactor leaves the attendance schema and its existing migrations unchanged; concurrent daily-expense schema work is separate.
- Attendance dashboard/history/report selects exclude raw evidence. Device display selects exclude credential IDs, public keys and counters. Decimal financial calculations remain on the server; JSON serialization keeps Prisma Decimal amounts as strings.
- `public/sw.js` installs/activates without a fetch handler or background queue, so it does not cache protected API responses or queue attendance writes offline.

## Server display cache and deployment

Only the first 100 ID/name choices plus count for departments, offices and shifts are persistently cached. Authorization precedes cache access. The actual role matrix grants authorized administrators the same organization-wide reference options, so there is no office-specific scope to add to these three keys. Employee choices, searches, other pages, policies, credentials, attendance, reports and authorization remain dynamic.

The cache is process-local. The supplied one-process deployment can retain it. Set `REFERENCE_DISPLAY_CACHE=disabled` in **every** worker when deploying multiple processes/replicas without coordinated cache invalidation; this uses direct reference reads and introduces no infrastructure. Actual topology is an operator concern, not something verified from the example. A failed expiry bypasses only the affected process, so this is not a substitute for that multi-worker setting.

Direct database edits bypass both application invalidation mechanisms. With this cache enabled, display choices can remain stale until revalidation/expiry; operational acceptance still uses fresh data. Use the application write endpoints or disable the display cache for workflows involving frequent direct edits. HTTP `no-store` controls the browser/proxy HTTP cache; it does **not** disable RTK Query's separate in-memory cache.

No live migrations, infrastructure edits, live restarts or deployment were performed. Existing migrations were applied only to disposable local PostgreSQL for integration/browser verification. Rollback is an application code/dependency rollback: no data conversion is required. Preserve the sensitive-response fixes and authorization boundaries if reverting only the client state migration.
